One fix, and it is the one that matters if you installed v0.4.5 through the installer.

## Fixed

- **The MSI upgrade registered the new version and kept the old files.** v0.4.5's installer ran, wrote 0.4.5 into the registry, and left v0.4.4's files on disk — so the app started as v0.4.4, saw a newer release, and updated again on every start. Two things let that happen: every release's assemblies carried the same file version (0.1.7.0, from a build property nobody bumped), and the installer removed the previous version only *after* copying the new files, at which point Windows Installer's rule of never replacing a file with the same version had already kept every one of them. The workflow now stamps every assembly with the release's version, and the installer removes the previous version before it copies — either alone would have prevented this; both are in.

Installing this release over the broken state puts the right files in place. Nothing else changed.
