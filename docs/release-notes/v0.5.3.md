A release for League patch 16.21. Riot changed how material names are stored in map and skin bins, and without this update no 16.21 material loads. Map visibility now follows the game's own rules, so what the editor hides is what the game hides. Export .fantome writes LTK's new `game_data.yaml` declarations. Two Direct3D 11 lighting bugs are fixed.

## Added

- **League 16.21 support.** In 16.21, a material's name is stored as an 8-byte hash instead of text.
  - ReyEngine reads and writes the new form for maps, skins, the Material Editor, GameData declarations and Build Package/.fantome.
  - A project from before 16.21 is converted when it is saved.
  - A 16.21 project's own materials show by name in the Materials tab. The open map supplies the names.
- **A visibility check under Visibility Layers.** It lists what the game would never show:
  - controller graphs that can never be on;
  - terrain controllers that rely on the Base bit, which the game never counts;
  - Riot's own controllers with extra bits;
  - ALL controllers with more than two parents.
- **Ritobin text shows 16.21 material names** as `hash[u64] = 0x…`, the same form ltk_ritobin 0.11 uses. Typing a name as `hash[u64,xxh3] = "…"` also works.

## Improved

- **Map visibility follows the game.** Visibility controllers are evaluated the way the client evaluates them:
  - parent modes ALL, ANY, ONE and NONE;
  - named controllers that start hidden;
  - terrain controllers that show only while one of their rifts is in play.

  A map that looked right in the editor but came up empty in the game now looks empty in the editor too. **Lenient controllers** under Visibility Layers brings back the old, kinder reading for the current session.
- **Export .fantome writes `META/game_data/<layer>/game_data.yaml`,** LTK's new place for declarations.
  - LTK Manager 1.32 and newer read the YAML file.
  - The declarations are also still written into `info.json`, so LTK Manager 1.31 and older still read them.
  - **Import .fantome** reads both forms.

## Fixed

- **Lights too bright on first load.** On Direct3D 11, a map's lights started far too bright until you switched the renderer and back. They now use Riot's lighting from the first frame.
- **Light through buried surfaces.** On Direct3D 11, the dynamic-light overlay no longer lets a buried surface add its light to the surface above it.
