This release makes SRX_DynamicEffect lightmap UV generation an explicit creator choice and makes repeated layout passes safe.

## Added

- **Generate lightmap UVs for SRX_DynamicEffect meshes (Experimental)** is now available directly in the Lightmap Layout card.
- The option is off by default. When checked, uncovered DynamicEffect meshes receive UV7 and atlas assignments; when unchecked, they remain outside the generated layout.
- Layout status now explains that animated, render-region and opted-out DynamicEffect meshes may remain intentionally without UVs.

## Fixed

- Incremental layout generation now starts at the next unused atlas index. Enabling DynamicEffect after a static-only layout therefore creates a new atlas instead of overlapping or replacing `0.tex`.
- The completion message reports intentionally excluded meshes instead of leaving the remaining count unexplained.

## Verified

- The existing Winter Rift layout's 159 unlit meshes were identified as 147 VertexDeform meshes and 12 render-region Faelight indicators; none are DynamicEffect.
- On pristine Milkshake geometry, a conservative first pass left all 83 DynamicEffect meshes unmodified and generated four static atlases.
- A second pass with the option enabled added UV7 and lightmap assignments to all 83 DynamicEffect meshes in a new atlas at index 4, without reusing the first pass's atlas names.
- All 305 automated tests pass and the Release application builds successfully.
